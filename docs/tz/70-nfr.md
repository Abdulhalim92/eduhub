# 70. Нефункциональные требования

Источники: `docs/spec/src/70-nfr.md` (`NFR-SEC-*`, `NFR-REL-*`), `.claude/rules/security.md`.

## Безопасность

| Область | Требование |
|:--|:--|
| Изоляция | RLS на каждой таблице центра, автоматический тест покрытия (`20-data-model.md`) |
| Аутентификация | Короткий access JWT, refresh с ротацией, argon2id, лимиты кодов и паролей (`30-auth-rbac.md`) |
| Авторизация | RBAC плюс принадлежность центру в каждом обработчике; запрет по умолчанию |
| Ввод | Валидация DTO на границе, allow-list для файлов и адресов, защита от SSRF и path traversal |
| Данные | Секреты только из окружения или менеджера секретов; ключи эквайринга шифруются; в логах нет ПДн, паролей, токенов, номеров карт |
| Транспорт | Только TLS, HSTS, строгие `CORS` для известных клиентов |
| Зависимости | `govulncheck` и проверка лицензий в CI; запрещены MD5 и SHA-1 для безопасности |
| Журнал | Неизменяемый, цепочка хэшей (`BR-010`, `NFR-SEC-020`) |
| Персональные данные детей | Блок отложен (`Q-014`). Архитектура: состав ПДн локализован в `students` и `guardians`, доступ только по ролям, логи без ПДн, шифрование хранилища, возможность выгрузки и удаления данных |

## Производительность (цели для старта, подтвердить `Q-027`)

- p95 чтения основных экранов не более 300 мс на сервере, записи не более 500 мс.
- Список с фильтрами и пагинацией использует индексы; запрет `SELECT *` и выборок без `tenant_id`.
- Отчёты по периоду считаются на сервере; тяжёлые (прибыль за год) через материализованное представление или кэш с инвалидацией.
- Базовая нагрузка для тестов: 500 центров, 50 000 учеников, 5 000 платежей в день.
- Фоновые задачи не блокируют запросы: блокировки короткие, батчи ограничены.

## Надёжность (`NFR-REL-010`)

- Резервная копия базы ежедневно и журнал WAL для восстановления на момент времени; RPO не более 24 часов, RTO не более 4 часов, доступность 99,5% в месяц.
- Резервные копии хранятся отдельно от основной базы (другая зона или хранилище), шифруются.
- Восстановление проверяется регулярно (не реже раза в квартал) на стенде, результат записывается.
- Миграции без простоя (`migrations.md`); откат релиза — через предыдущий образ и DOWN-миграцию, проверенную на копии.
- Корректное завершение: сервер перестаёт принимать запросы, дожидается текущих, воркер возвращает невзятые задачи.

## Размещение (`NFR-REL-020`, `Q-024`)

- Облако в стране. До выбора провайдера: контейнеры, конфигурация переменными окружения, 12-factor, нет привязки к сервисам конкретного облака.
- Нужны: PostgreSQL (управляемый или собственный), S3-совместимое хранилище, секрет-хранилище, мониторинг. Если управляемого PostgreSQL нет, добавить эксплуатацию: обновления, репликация, бэкапы, мониторинг (оценка работ — на владельце после `Q-024`).
- Окружения: разработка, стенд (демоданные из `cmd/seed`), продуктив. Продуктив изолирован по доступам.

## Наблюдаемость

- Структурные логи `slog` с `request_id`, `tenant_id`, `actor_id` (без ПДн).
- Метрики: HTTP (RPS, латентность, ошибки), БД (пул, медленные запросы), outbox (глубина, `dead`), SMS (отправлено, ошибки), вебхуки (принято, отклонено), подписки по состояниям.
- Алерты: рост ошибок 5xx, разрыв цепочки аудита, расхождение кэша и журнала баланса, рост `dead`, неудачная резервная копия.
- Трассировка запросов по OpenTelemetry для внешних вызовов.

## Доступность и языки

Все тексты через словари (ru, tg), форматы дат и чисел по локали, сомони как «сом.» или «TJS» по настройке клиента. Требования к доступности интерфейса — `Q-027`.

## Эксплуатация

- Конфигурация: единый загрузчик, проверка обязательных переменных при старте.
- Health: `/healthz` (живость), `/readyz` (БД и миграции).
- Релизы: CI собирает, прогоняет проверки (`go build`, `go vet`, `go test -race`, `golangci-lint`, `govulncheck`), публикует образ. Продуктив обновляется вручную подтверждением.
