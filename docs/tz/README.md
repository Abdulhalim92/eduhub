# ТЗ на бэкенд платформы «Линия»

Техническое задание для внутренней команды бэкенда (Go). Источник требований — `docs/spec/src/` (версия 2.4); ТЗ не повторяет требования, а описывает, как их реализовать, и ссылается на идентификаторы `PLT-…`, `CTR-…`, `LRN-…`, `SYS-…`, `BR-…`, `NFR-…`, `Q-…`. При расхождении правит спецификация, а не ТЗ.

Статус: черновик 1. Сроки, состав команды и бюджет намеренно пусты, их добавит владелец (`90-plan.md`).

## Как читать

1. Начать с `00-overview.md` и `10-architecture.md`.
2. Перед любой работой с деньгами прочитать `40-money.md` и `.claude/rules/money.md`.
3. Перед новой фичей: `go-planner` (план), согласование, `go-coder`, `go-reviewer`, `go-tester` (`.claude/rules/workflow.md`).
4. Новое требование в спецификации получает строку в `85-traceability.md`.

## Правила проекта, обязательные для кода

`.claude/rules/go.md`, `db.md`, `migrations.md`, `money.md`, `security.md`, `architecture.md`, `workflow.md`. Главные из них: нет кода без падающего теста, деньги только `int64` в дирамах, мутации идемпотентны, платежи не удаляются (сторно), каждая запись денег в аудите.
