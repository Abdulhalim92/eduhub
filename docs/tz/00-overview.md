# 00. Обзор

## Цель

Заменить mock-слой `api` из прототипа (`src/js/core/api.js`) реальным бэкендом, не меняя экраны: сигнатуры и пути «метод → REST» из шапки `api.js` остаются контрактом, новые функции спецификации 2.4 добавляются поверх.

## Что делает система

«Линия» — B2B2C Multi-Tenant SaaS для учебных центров Таджикистана (сомони, русский и таджикский языки). Три контура:

1. **Платформа** (SuperAdmin и команда): центры, тарифы и подписки, счета, баланс на платформе и овердрафт, SMS-пакеты, магазин методик, модерация каталога, журнал платформы, режим поддержки.
2. **Центр**: сотрудники, ученики, группы, расписание, посещаемость, начисления и платежи учеников, сверка, расходы, зарплата, баллы.
3. **Ученик и родитель**: единый аккаунт по телефону, расписание, оплата и долг, баллы, уведомления. На первом этапе — Telegram-бот и Mini App.

## Принятые решения владельца (обязательны)

| Тема | Решение | Где в спецификации |
|:--|:--|:--|
| Изоляция | Общая схема PostgreSQL, `tenant_id` в каждой строке, защита на уровне строк (RLS) | `NFR-SEC-010` |
| Аккаунты | Единый аккаунт по телефону, основной вход по SMS-коду; логин и пароль — запасной вариант | `SYS-ACC-030`, `BR-035` |
| Роли | Владелец, администратор, кассир, преподаватель, менеджер, ученик, родитель; роль привязана к паре «человек + центр» | `01-roles`, `BR-035` |
| Команда платформы | Владелец платформы, менеджер по клиентам, финансы, модератор, поддержка (только чтение) | `01-roles` |
| Режим поддержки | Только чтение, без финансов, с причиной, таймером; центр видит запись о входе | `PLT-CTR-050` |
| Деньги учеников | Платформа не принимает и не хранит их, только фиксирует | `BR-026` |
| Приём оплаты | Касса, эквайринг центра, p2p-кошелёк сотрудника | `CTR-FIN-060` |
| Платёж | Вносит кассир («Принят»), администратор сверяет («Сверен»), отмена только сторно | `CTR-FIN-020`, `CTR-FIN-070`, `BR-031` |
| Начисление | На связку «ученик + группа» за месяц; сумму задаёт центр; просрочка с 1-го числа | `BR-028`, `BR-029` |
| Ученик в группах | Любое число групп | `Q-020` закрыт |
| Баллы | Отдельный баланс, лоты со сроком жизни, источник только успехи и автоправила | `BR-030` |
| Тариф платформы | Лимиты по сотрудникам, хранилищу, филиалам; бесплатный «Старт»; овердрафт центра остаётся | `Q-001`, `Q-002` |
| Окончание подписки | 7 дней льготы, затем «только чтение», через 30 дней блокировка, данные не удаляются | `BR-034` |
| Языки | Русский и таджикский | `SYS-I18-010` |
| Размещение | Облако в стране; контейнеры без привязки к провайдеру | `NFR-REL-020`, `Q-024` |
| Валюта | Только сомони | `BR-027` |
| Пилот | Реальных центров нет; данные демонстрационные, нужен генератор | `90-plan.md` |
| Юридические вопросы | Отложены (`Q-014`, `Q-026`) | `NFR-SEC-050` |

## Допущения без подтверждения владельца

Помечены `Q-028`…`Q-031`: статусы платежа и роли кассира и администратора, параметры баллов, расходы и зарплата, канал родителя и состав команды платформы. Реализовывать как описано в ТЗ, но не считать окончательными: изменение должно быть дешёвым (конфигурация, а не перепроектирование).

## Что не входит в первую версию

- Публичный API и white-label приложение для центров.
- Нативное мобильное приложение родителя (только Telegram-бот и Mini App).
- Приём денег платформой от учеников, мультивалютность, фискальные чеки.
- Продажа собственных курсов центров другим центрам (`Q-008`).
- AI-помощник, единый ящик заявок из мессенджеров.
- Платное продвижение в каталоге.
- Соответствие закону о персональных данных: блок отложен до юридического заключения; архитектура не должна мешать его добавлению (`Q-014`).

## Термины
