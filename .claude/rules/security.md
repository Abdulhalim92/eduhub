## Никогда не делать
- Не логировать PII (контакты родителей/детей, номера телефонов, адреса) сверх необходимого.
- Не собирать SQL строками — только параметризация.
- Не хранить секреты в репозитории.

## Чеклист
### Валидация входа
- XSS/SSRF/path traversal — валидация и allow-list где возможно.
- Rate limiting на публичных эндпоинтах (поиск, регистрация, отправка отзыва).

### Аутентификация и авторизация
- AuthN: bcrypt/argon2 для паролей, TLS everywhere, валидация токенов + срок жизни + ротация.
- AuthZ: RBAC-проверки на каждом endpoint по ролям SRS §3 (Гость → Родитель/студент → Учреждение → Модератор → Администратор МОН).

### Зависимости
- Проверять CVE (govulncheck / npm audit) в CI.
- Избегать небезопасной криптографии (MD5/SHA1).

### Целостность данных EduHub
- Минимизация данных о детях; контактные данные — только по необходимости (NFR CLAUDE.md).
- Audit log действий модерации — кто/когда/что изменил в статусе учреждения/отзыва.
- OWASP Top 10 — защита на входе (transport) и на границе БД.
