## Базовая информация

- **Тип API:** REST (JSON) | gRPC | GraphQL
- **Базовый URL:**
  - Production: `https://api.example.com`
  - Staging: `https://api-staging.example.com`
- **Версионирование:** через URL (`/v1/`, `/v2/`).
- **Полная спецификация:** [openapi.yaml](../openapi.yaml) или Swagger UI по адресу `/docs`.

---

## Аутентификация

- Метод: **Bearer JWT** в заголовке `Authorization: Bearer <token>`.
- Получение токена: `POST /v1/auth/login` (email + password) или OAuth-провайдер.
- Время жизни access-токена: **15 минут**.
- Refresh-токен: **30 дней**, обновление через `POST /v1/auth/refresh`.

Эндпоинты, не требующие авторизации:
- `POST /v1/auth/login`
- `POST /v1/auth/register`
- `GET /v1/health`

## Формат запросов и ответов

### Успешный ответ

```json
{
  "data": { ... },
  "meta": {
    "requestId": "uuid"
  }
}
```

### Ответ с пагинацией

```json
{
  "data": [ ... ],
  "meta": {
    "page": 1,
    "perPage": 20,
    "total": 153,
    "totalPages": 8
  }
}
```

### Ошибка

```json
{
  "error": {
    "code": "ORDER_NOT_FOUND",
    "message": "Order with id 'abc' not found",
    "details": { ... }
  },
  "meta": {
    "requestId": "uuid"
  }
}
```

## HTTP-коды

| Код | Когда используем |
|-----|------------------|
| 200 | Успешный GET, PATCH, DELETE |
| 201 | Успешный POST (создание ресурса) |
| 204 | Успех без тела ответа |
| 400 | Ошибка валидации запроса |
| 401 | Не авторизован (нет токена / токен невалидный) |
| 403 | Авторизован, но нет прав |
| 404 | Ресурс не найден |
| 409 | Конфликт (например, дубликат) |
| 422 | Валидация прошла, но бизнес-правило нарушено |
| 429 | Rate limit |
| 500 | Внутренняя ошибка сервера |
| 503 | Сервис недоступен (зависимость упала) |

## Коды ошибок (внутренние)

Все коды в `SCREAMING_SNAKE_CASE`. Полный реестр — в `shared/errors/codes.ts`.

| Префикс | Контекст |
|---------|----------|
| `AUTH_*` | Аутентификация |
| `ORDER_*` | Заказы |
| `USER_*` | Пользователи |
| `PAYMENT_*` | Платежи |
| `VALIDATION_*` | Валидация запроса |

## Соглашения по эндпоинтам

- **Имена ресурсов:** существительные во множественном числе (`/orders`, `/users`), kebab-case для составных (`/payment-methods`).
- **Идентификаторы:** UUID v4 в пути (`/orders/{orderId}`).
- **Фильтрация:** query-параметры (`?status=pending&customerId=...`).
- **Сортировка:** `?sort=createdAt:desc` или `?sort=-createdAt`.
- **Поиск:** `?search=...`.
- **Пагинация:** `?page=1&perPage=20`. Максимум `perPage=100`.

---

## Rate Limiting

- Лимит по умолчанию: **100 запросов/минута на токен**.
- Лимиты возвращаются в заголовках: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.
- При превышении — `429 Too Many Requests` с `Retry-After`.

---

## Идемпотентность

Для `POST` операций, которые могут быть повторены клиентом (создание заказа, платёж), поддерживаем заголовок `Idempotency-Key`. Ключ хранится 24 часа.

## Версионирование и deprecation

- Минимум 2 версии живут одновременно.
- Об устаревании предупреждаем заголовком `Deprecation: true` и `Sunset: <date>` минимум за **3 месяца** до выключения.
- В changelog отмечаем breaking changes явно.
