# Workflows — индекс

> **Назначение:** список ключевых бизнес-процессов проекта. Каждый процесс — отдельный файл с пошаговым описанием.
> **Обновлено:** YYYY-MM

---

## Как пользоваться

- Один процесс = один файл.
- Имя файла: `kebab-case`, отражает суть (`order-creation.md`, а не `process1.md`).
- В таблице ниже — одна строка на процесс с кратким описанием.
- Новый процесс → создать файл по [шаблону](#шаблон-нового-процесса) + добавить строку в таблицу.

## Шаблон нового процесса

Используй структуру файла [order-creation.md](./order-creation.md) как образец. Минимально процесс должен содержать:

1. **Цель и контекст** — зачем процесс существует.
2. **Триггер** — что его запускает.
3. **Участники** — какие модули/сервисы задействованы.
4. **Шаги** — пронумерованный список с указанием слоя (Presentation/Application/Domain/Infrastructure).
5. **Альтернативные сценарии** — ошибки, edge cases.
6. **Side effects** — что происходит за пределами основного потока (события, нотификации, аналитика).
7. **Диаграмма** — sequence diagram через Mermaid.
