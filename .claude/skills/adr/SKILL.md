# ADR (архитектурные решения)

## Шаги выполнения

1. **Уточни контекст** — если пользователь не указал, спроси:
   - Краткое название решения (2–5 слов для имени файла)
   - Какую проблему решаем и почему именно сейчас
   - Какие варианты рассматривались (хотя бы два)
2. **Найди следующий номер** — прочитай `docs/adr/`, найди последний `NNNN-*.md`, следующий = N+1. Если директория пустая или не существует — создай её, номер = `0001`.
3. **Создай файл** `docs/adr/NNNN-<краткое-название>.md` по шаблону из `.claude/skills/adr/templates/adr.md.tmpl`. Заполни все секции осмысленно.
4. **Покажи результат** — выведи путь к файлу и краткое резюме решения. Спроси нужны ли правки.

## Расположение файлов

```
docs/adr/NNNN-краткое-описание.md
```

Нумерация: последовательная, с ведущими нулями (`0001`, `0002`, ...).

## Когда писать ADR

- Выбор БД, брокера или фреймворка
- Изменение границ сервисов
- Новые паттерны интеграции (синхронные vs асинхронные)
- Изменение модели безопасности
- Ломающие изменения API
- Решения по денормализации данных

## Правила

- ADR неизменяемы — новые решения замещают старые через новый ADR со ссылкой
- Максимум 1 страница — написан для нового члена команды
- Фокус на ПОЧЕМУ, а не КАК
- Содержимое на русском (технические термины допустимы на английском)
