# Миграции PostgreSQL

## Шаги выполнения

1. **Уточни изменение** — если не указано: какую таблицу/колонку/индекс затрагивает, есть ли данные для backfill.
2. **Прочитай текущую схему** — найди DDL-файл или существующие миграции в репозитории, чтобы знать текущую структуру.
3. **Проверь по таблице запрещённых операций** — нет ли даунтайм-рисков.
4. **Сгенерируй имя файла** — `YYYYMMDDHHMMSS_краткое_описание.sql` (timestamp = текущий момент).
5. **Создай файл** — найди директорию миграций в проекте (`migrations/`, `db/migrations/`, `schema/migrations/` и т.п.) и положи туда. Если директории нет — спроси у пользователя.
6. **Покажи результат** — путь к файлу + краткое резюме UP/DOWN. Спроси нужны ли правки.

## Запрещено (вызывает даунтайм)

| Операция | Проблема | Безопасная альтернатива |
|----------|----------|------------------------|
| `ALTER TABLE ADD COLUMN NOT NULL` без DEFAULT | Перезапись таблицы | Nullable → backfill батчами → SET NOT NULL |
| `ALTER COLUMN TYPE` | Полная перезапись таблицы | Новая колонка → миграция данных → удалить старую |
| `CREATE INDEX` без CONCURRENTLY | Блокировка таблицы | `CREATE INDEX CONCURRENTLY` вне транзакции |
| `DROP COLUMN` сразу | Ломает работающие запросы | Убрать из кода → деплой → потом дроп |
| `LOCK TABLE` | Блокирует весь доступ | Row-level locks |

## Безопасные паттерны

1. **Новая NOT NULL колонка**: добавить nullable → заполнить батчами → `ALTER TABLE SET NOT NULL`
2. **Новый индекс**: `CREATE INDEX CONCURRENTLY` — вне блока транзакции (отдельный файл миграции)
3. **Переименование колонки**: новая колонка → копия данных → переключение кода → удаление старой (3 деплоя)
4. **Новое значение enum**: `ALTER TYPE ... ADD VALUE` — вне транзакции

## Типы данных

| Назначение | Тип |
|-----------|-----|
| Деньги | `BIGINT` в дирамах (см. `.claude/rules/money.md`) |
| Даты/время | `TIMESTAMPTZ` |
| ID | `UUID` с `gen_random_uuid()` |
| Статус | `TEXT` + CHECK constraint (не enum — проще расширять) |

## Правила для денег и аудита

- Финансовые таблицы: только soft-delete (`deleted_at TIMESTAMPTZ NULL`)
- Audit-колонки везде: `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Большие таблицы (transactions, audit_log): партиционировать по диапазону дат

## Чеклист

- [ ] UP + DOWN присутствуют
- [ ] Нет блокирующих операций (см. таблицу выше)
- [ ] Индексы с CONCURRENTLY и вне транзакции
- [ ] BIGINT (дирамы) для денег, TIMESTAMPTZ для дат
- [ ] Soft-delete для финансовых записей
- [ ] Проверено на копии данных production-размера
