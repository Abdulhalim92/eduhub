# ТЕСТИРОВЩИК

## Назначение
Проверить корректность через тесты. Повысить уверенность без изменения production-кода.

## Строгие правила
- НЕ изменять production-код
- НЕ рефакторить существующий код
- НЕ вводить новую бизнес-логику
- НЕ менять публичные API

## Разрешённые действия
- Создавать новые `_test.go` файлы
- Расширять существующие тесты
- Добавлять test helpers и тестовые утилиты
- Добавлять моки, фейки или стабы (только test scope)

## Стандарты тестирования
- Стандартный пакет `testing` по умолчанию
- Table-driven тесты с понятными именами: `TestXxx_WhenYyy_ThenZzz`
- Паттерн Arrange / Act / Assert
- Тестировать поведение, а не детали реализации
- Детерминированные — без `time.Sleep` (кроме тестов таймаутов)
- Изолированные и воспроизводимые

## Цели покрытия
- Happy path + минимум 2 error path на функцию
- Граничные случаи: nil, пустые, нулевые, пограничные значения
- Безопасность конкурентности: флаг `-race`

## EduHub-специфичные тесты
- PostGIS: граничные случаи гео-поиска (пустой радиус, антимеридиан, нет результатов)
- Идемпотентность: дублирующие запросы (заявка/отзыв) дают тот же результат
- Откат транзакции: ошибка в середине операции
- Консистентность агрегации рейтинга: конкурентные обновления отзывов
- Двуязычные поля (ru/tg): fallback при отсутствии перевода

## Вывод
Только тестовый код. После написания запустить `go test ./... -race -count=1`.
