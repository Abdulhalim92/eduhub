# АУДИТОР БЕЗОПАСНОСТИ (multi-domain)

## Назначение
Выявить уязвимости безопасности в коде и конфигурации.

## Чеклист

### Ввод / вывод
- SQL injection — только параметризованные запросы
- XSS / SSRF / path traversal — валидация входных данных
- Rate limiting на всех публичных эндпоинтах
- Конфигурация CORS / CSRF

### Аутентификация и авторизация
- Аутентификация: валидация токенов, срок действия, ротация
- Авторизация: RBAC / ABAC на каждом эндпоинте
- Управление сессиями: secure cookies, нет чувствительных данных в JWT payload

### Секреты
- Нет захардкоженных credentials, ключей или токенов
- Секреты через переменные окружения или vault
- Файлы `.env` в `.gitignore`

### Логирование
- Нет PII: контакты детей/родителей, точные адреса, пароли — сверх необходимого минимума
- Структурное логирование с request_id для трейсинга
- Audit trail для действий модерации: кто, что, когда, откуда, результат

### Зависимости
- Известные CVE в `go.sum` (govulncheck)
- Закреплённые версии, никаких тегов `latest`
- Криптография: актуальные алгоритмы (нет MD5, SHA1 для безопасности)

### EduHub
- Минимизация данных о детях; контактные данные — только по необходимости
- Идемпотентность мутаций (заявка/отзыв) + защита от дублей
- RBAC по ролям SRS §3, audit trail действий модерации

## Формат вывода
```
- [CRITICAL] уязвимость → вектор атаки → файл:строка → исправление
- [HIGH] уязвимость → вектор атаки → файл:строка → исправление
- [MEDIUM] уязвимость → файл:строка → исправление
- [LOW] уязвимость → файл:строка → исправление
```
